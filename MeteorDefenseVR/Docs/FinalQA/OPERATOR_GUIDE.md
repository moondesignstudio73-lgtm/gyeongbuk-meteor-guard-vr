# METEOR DEFENSE — PC 시연용 운영 안내

빌드 식별 정보는 같은 폴더의 `BUILD_IDENTITY.json`에서 확인하세요. `LOCAL_PREVIEW.txt`가 있으면 로컬 검증본이며 납품 승인본이 아닙니다. 빌드 생성과 실제 Windows/웹캠/HMD 장시간 운영 검증은 별개입니다. 운영 전 담당자에게 해당 빌드의 검증 기록과 남은 제한을 확인하세요.

## 실행

이 안내 파일과 같은 폴더의 `MeteorDefenseVR.exe`를 더블클릭합니다. Unity Editor는 필요 없습니다.
다른 PC로 옮길 때는 담당자가 승인한 **단일 버전 패키지 폴더**를 통째로 복사하세요. `MeteorDefenseVR_Data`, `MonoBleedingEdge`, DLL, 설정 및 고지 파일 등 동봉 파일이 필요하므로 exe만 복사하지 마세요. 개발 저장소의 `Builds/Windows` 상위 폴더에는 과거 빌드가 함께 있으므로 전체를 복사하지 않습니다.
웹캠은 Windows 설정 → 개인정보 및 보안 → 카메라 → 데스크톱 앱 카메라 접근을 허용합니다.
다른 화상회의 프로그램이 카메라를 사용 중이면 먼저 종료하세요.

기본은 Public Experience + Auto 입력입니다. 실제 VR 눈 추적 → 웹캠 → 마우스 순으로 사용 가능한 입력을 선택합니다.
영상을 저장하거나 업로드하지 않습니다. 보정값은 세션 메모리에서만 사용하며 다음 체험자의 보정에서 다시 설정됩니다.

## 체험 방법

### 우주 안전 교육 훈련 (추가)

Ready의 **우주 안전 훈련 시작 · 약 12분**은 기존 짧은 START 게임과 별도 경로입니다. 이름/번호를 입력하고 난이도를 선택하면 기존 튜토리얼 뒤에 방향·거리 → 위험 예측 → 손상 원인/비상대응 → 종합훈련 → 개인 리포트가 이어집니다. 이름 입력은 PC 키보드로 운영자가 도울 수 있습니다. 재방문자는 튜토리얼 건너뛰기를 선택할 수 있지만 웹캠이 보정되지 않았으면 기존 보정을 진행합니다.

교육 기본 예산은 11분이며 튜토리얼/현재 과제 마무리 시간이 추가됩니다. 교육의 Easy도 여섯 방향을 배우되 도움을 더 제공합니다. 기존 짧은 게임의 Easy 전방 배치는 유지됩니다. 충돌 회피율은 이 게임의 레이저 방어로 충돌을 막은 비율이며, 기체 이동 회피 성공률은 아닙니다.

리포트에서 ‘다음 참가자’를 누르면 전투/계통/보정을 초기화하고 빈 참가자 입력 화면으로 돌아갑니다. 튜토리얼 건너뛰기는 OFF로 되돌립니다. 등록 화면에서는 입력 중 R/Enter가 게임 Reset/START로 작동하지 않으며 ‘돌아가기’ 버튼으로 나옵니다. 정상 Reset도 부분 교육 기록은 보존합니다. 일반 참가자 리포트에서는 이름 일부를 가립니다.

교사용 목록은 **Operator/Development 모드**의 Ready에서 ‘교사용 결과’로 엽니다. 오늘/전체, 5행 페이지, 학생 행의 상세 결과, UTF-8 BOM CSV 내보내기를 제공합니다. Public 모드에서는 교사용 진입을 숨깁니다. 별도 로그인 인증은 없으므로 운영 PC 접근을 관리해야 합니다.

교육 기록은 `%USERPROFILE%\AppData\LocalLow\DefaultCompany\MeteorDefenseVR\Education\MeteorDefense-education-v1.json`에 기본 최근 30일/최대 200건 저장됩니다. 교사가 명시적으로 내보낸 CSV는 `Education\Exports`에 저장됩니다. 영상·얼굴·보정값은 교육 기록에 포함하지 않습니다. **이름/번호는 직접 입력한 식별 정보이므로 기관 보관 정책에 따라 관리하세요.** 저장 실패 안내가 나오면 교사용 CSV로 실행 중 자료를 내보낼 수 있습니다.

교사용 ‘기록 전체 삭제’를 5초 안에 두 번 선택하면 JSON과 복구본을 비웁니다. 이미 내보낸 CSV는 별도 파일이므로 남습니다. 기존 익명 게임 랭킹과 교육 기록은 서로 다른 파일입니다. 상세 평가식/설정/검증 제한은 프로젝트 `Docs/EducationQA/REPORT.md`를 참조하세요. 실제 교육 현장 10~15분 체험과 실물 HMD 검수는 자동 검사와 별도로 필요합니다.

### 기존 짧은 운석 방어 게임

1. 화면의 START를 바라보거나 마우스를 올려 놓습니다. Enter/Space로도 시작됩니다.
2. 웹캠 보정에서는 고개를 편안히 고정하고 표시되는 다섯 점을 눈으로 따라갑니다.
3. 마우스를 움직이거나 웹캠에서 고개를 약간 돌려 유지하면 실제 카메라가 회전합니다. 중앙 시선점을 운석에 맞추면 LOCKING → LOCK ON → 자동 발사됩니다. 클릭할 필요가 없습니다.
4. 보스를 파괴하면 성공 연출, 실제 점수와 결과가 표시됩니다.
5. 결과 화면은 시간 제한 없이 유지됩니다. 기록을 확인한 뒤 `다시 출격` 또는 `기지 메뉴`를 선택합니다. 패배 시에는 귀환·착륙 연출이 끝난 뒤 결과가 표시됩니다.

## 격납고 메뉴

버튼을 약 0.7초 바라보면 진행 링이 채워지고 선택됩니다. 마우스 클릭도 가능합니다.

- **다시 하기**: 같은 사용자의 시선 보정과 선택 난이도를 유지하고, 전투 상태를 정리한 뒤 출격 카운트다운으로 연결됩니다.
- **난이도 변경**: 쉬움/보통/어려움/매우 어려움 선택판을 엽니다. 선택 후 ‘격납고로 돌아가기’를 누르세요. 이전 결과의 난이도는 바뀌지 않습니다. 운영자가 난이도를 잠그면 변경할 수 없습니다.
- **시선 재설정**: 기존 보정을 실행하고 격납고로 돌아옵니다. 튜토리얼은 다시 실행하지 않습니다.
- **랭킹**: 최근 임무 결과, TOP 10(5개씩 두 페이지), 난이도별 최고 기록을 확인합니다. ‘뒤로가기’로 원래 메뉴에 복귀합니다. 다음 사용자 대기 화면에서도 열 수 있습니다.
- **종료 / 대기**: 앱을 종료하지 않고 다음 사용자 대기로 전환합니다. 보정과 점수/전투 상태를 초기화하고, 기본 설정에서는 난이도가 보통으로 돌아옵니다. ‘새 체험 시작’은 Intro부터 진행합니다.

사용자가 바뀌면 ‘다시 하기’ 대신 **종료 / 대기 → 새 체험 시작**을 사용하세요. 비정상 상태에서는 기존 운영자 RESET/R로 귀환을 취소하고 원래 Ready로 복구합니다.

## 로컬 기록 운영

기존 짧은 게임의 완료 결과만 최근 100개 보관합니다. 점수·명중률·최종 HP 순으로 TOP 10을 정렬하며, 최고 기록은 현재 보관 중인 기록 기준입니다. 기존 Result의 Rank/명중률/최고 Combo/본게임 플레이 시간을 그대로 사용합니다. Reset, 다음 사용자 대기, 앱 재시작으로 기록이 지워지지 않습니다. 이 익명 게임 랭킹에는 이름·얼굴·웹캠 영상·보정값을 저장하지 않습니다. 위 교육 훈련의 명시적 참가자 입력·교육 기록과는 구분됩니다.

Windows 저장 위치: `%USERPROFILE%\AppData\LocalLow\DefaultCompany\MeteorDefenseVR\MeteorDefense-ranking-v1.json`. `.bak`는 복구 사본, `.tmp`는 임시 파일입니다. 날짜/시간은 PC 시계 기준입니다. 저장이 안 된다는 안내가 나오면 이번 실행 중에는 확인할 수 있지만 종료 후 최신 기록은 남지 않을 수 있습니다. 게임은 계속 진행할 수 있습니다.

초기화하려면 **게임을 완전히 종료한 뒤** 위 이름의 `.json`, `.json.bak`, `.json.tmp` 세 파일만 삭제하세요. 다른 파일/폴더는 삭제하지 마세요. 삭제 전 필요하면 운영자가 별도 사본을 보관하세요. Unity에서는 `Meteor Defense → Local Ranking → Clear local records...`의 확인 대화상자를 사용할 수 있습니다. 일반 체험자 메뉴에는 기록 삭제 버튼이 없습니다.

게임 중 마우스는 숨겨지고 화면 중앙에 잠깁니다. 메뉴에서는 커서가 다시 나타납니다. 웹캠을 쓰지 않으려면 `Start-Mouse.cmd`를 실행합니다.

### HMD 없는 360° 테스트

`Start-VRSimulation.cmd`는 개발자 모드 + Windows VR Simulation + 웹캠 끄기로 실행합니다. 일반 Mouse 모드도 동일한 360° 자유 시점입니다. 마우스로 둘러보고 작은 중앙 시선점을 운석에 맞추면 자동 공격합니다. ESC는 커서 해제/일시정지, `게임으로 돌아가기` 또는 ESC는 재잠금입니다. 보정 중에는 재개해도 커서를 잠그지 않습니다. R/RESET은 초기 방향과 기본 난이도로 복귀합니다. Ready·결과·격납고에서는 항상 커서가 해제됩니다.

쉬움은 전방 중심, **보통부터 360° 탐색**입니다. 보통은 방향·거리 경고, 어려움은 방향만, 매우 어려움은 급한 위협 화살표 한 개와 점수 ×2를 사용합니다. 전방위 위협은 헤드폰을 권장합니다. 설정은 `PcTestSystem > WindowsVRSimulation`, 난이도별 생성·경고 수치는 각 `Difficulty_*` 에셋에서 조절합니다.

Ready/일시정지/격납고의 **시점 설정**에서 마우스 감도 0.1–2.0, 상하 반전, 시선점 표시, 흔들림 강/약/끔을 변경합니다. 기본 흔들림은 끔이며 **HMD에서는 항상 인위적 흔들림이 꺼집니다**. PC의 강/약도 최대 0.12°/0.04°, 0.1초의 미세 피격 반응입니다. 이 설정은 현재 앱 실행 동안 유지됩니다.

웹캠은 눈동자 화면 좌표와 별도로 얼굴 방향을 읽습니다. 정면을 기준으로 고개를 약간 돌려 유지하면 그 방향으로 계속 회전하고 정면으로 돌아오면 멈춥니다. 실제 고개를 180° 돌릴 필요는 없습니다. ESC로 쉬고 정면을 본 상태에서 재개하면 머리 기준을 다시 잡습니다. 얼굴 인식이 끊기면 회전이 멈추고 기존 시간 기준에 따라 마우스로 전환됩니다. 실제 웹캠 회전 부호·중립 위치·피로도는 행사 전 반드시 확인하세요.

실제 XR 장치가 동작하면 시뮬레이터가 HMD 카메라 자세를 덮어쓰지 않습니다. 이는 Quest 연결 검수 완료를 의미하지 않습니다. 상세 검증 범위는 `Docs/WindowsSimulationQA/REPORT.md`를 확인하세요.
일반 웹캠 입력은 근사 시선 입력이며 HMD의 실제 Eye Tracking과 동일한 정확도를 의미하지 않습니다.
아이가 달라지거나 의자/화면 위치가 바뀌면 새 체험을 시작해 다시 보정하세요.

## 운영 모드

| 실행 | 화면 |
|---|---|
| MeteorDefenseVR.exe | Public: 게임 UI만 표시 |
| Start-Operator.cmd | INPUT MODE / RESET / EXIT |
| Start-Development.cmd | 입력 진단, 영상 미리보기 선택, F1–F7 단계 이동, 키 설명 |

Public에서도 **R = 긴급 초기화**, **ESC = 일시정지/재개**가 작동합니다. ESC로 앱을 종료하지 않습니다. 운영자 EXIT 또는 Windows 창 닫기로 앱을 종료합니다.
Operator의 INPUT MODE에서 입력을 바꾸거나 웹캠을 다시 보정할 수 있습니다.
개발용 단계 이동은 Development에서만 허용됩니다.

### 외부 모니터 관전

- 기본은 `Mirror View`: 기존 플레이어 시점을 Windows 게임 창으로 표시합니다. 별도 관전 카메라가 기본으로 렌더링되지 않습니다.
- Operator/Development 하단 중앙 `SPECTATOR VIEW · 관전 시점으로 전환` 버튼으로 고정 측면 관전을 선택하고, 같은 자리의 `MIRROR VIEW` 버튼으로 복귀합니다. 이 버튼은 모니터 전용이며 Public에는 숨깁니다.
- 관전 모드에서도 HP·남은 운석·점수·Lock-On을 모니터 HUD에서 확인합니다. 출력 선택은 게임 Reset 이후에도 유지됩니다.
- Inspector: `PcTestSystem → Desktop Spectator Controller → Settings`. 기본 Spectator **1280×720 / 최대 30fps**, 해상도와 FPS는 추가 관전 렌더에만 적용합니다. HMD FPS는 제한하지 않습니다. Mirror 해상도는 게임 창/XR runtime 설정을 따릅니다.
- PC 마우스로 직접 플레이할 때는 Mirror를 사용하세요. 관전 카메라의 별도 화면 좌표로 기존 마우스 조준을 재매핑하지 않습니다.
- 확장 모니터는 게임 창을 해당 화면으로 옮기거나 Windows 디스플레이 복제를 사용합니다.
- 현재 프로젝트의 OpenXR loader/헤드 추적 rig는 아직 구성·실기기 검수되지 않았습니다. Quest Link/Air Link PCVR 어댑터만 준비된 상태이며 실제 HMD 동시 출력 완료를 의미하지 않습니다. Quest 단독 Android의 PC 관전은 별도 캐스팅 구성 필요; 이번 작업은 네트워크 스트리밍을 추가하지 않습니다.
- 검증 및 제한: `Docs/SpectatorQA/REPORT.md`. Windows exe 자동 실행/통신 검증 보류는 그대로 유지합니다.

## 현장 설정

실행파일 옆 `MeteorDefense-settings.json`을 메모장으로 열고 저장한 뒤 게임을 다시 실행합니다.
잘못된 범위는 안전 범위로 제한되며 JSON 문법이 잘못되면 Inspector 기본값을 사용합니다.

| 항목 | 값 / 기본값 |
|---|---|
| experienceMode | 0 Public / 1 Operator / 2 Development; 기본 0 |
| inputMode | 0 Auto / 1 VR / 2 Webcam / 3 Mouse / 4 Center / 5 Simulation; 기본 0 |
| lockDuration | 0.5–0.8초; 기본 0.65 |
| gameDuration | **본게임 운석 웨이브만** 40–60초; 기본 46. 전체 체험 시간 아님 |
| meteorDifficulty | 0 Gentle / 1 Standard; 기본 0 |
| webcamGazeAssist | true: 작은 조준 여유·0.25초 타깃 유예 / false: 최소 보조 |
| audioVolume | 0–0.7; 기본 0.65. 처음에는 낮은 음량으로 확인 |
| debugUI | Development 진단 UI 표시 여부; Public에서는 true여도 숨김 |
| operatorControls | R와 운영 버튼 사용 여부; 기본 true 유지 권장. ESC 일시정지는 공통 안전 기능 |

Unity에서는 MeteorDefense Scene → PcTestSystem → Experience Configuration에서 같은 값을 조정합니다.
Inspector의 Apply operation tuning은 Play 중 타이밍/난이도/음량을 적용합니다. 입력 모드는 다음 실행부터 적용하거나 Operator 메뉴에서 변경합니다.
보조는 제한된 충돌체 크기와 가까운 시선 범위에만 적용됩니다. 임의의 방향을 보아도 맞는 전역 자동 조준은 없습니다.

## 연속 운영 전 확인

- 조명이 얼굴에 고르게 닿도록 하고 역광을 피합니다.
- START부터 결과·격납고 귀환·다시 하기·다음 사용자 대기까지 실제 웹캠으로 확인합니다. 운영자 Reset도 별도로 확인합니다.
- 잠깐 얼굴을 벗어나면 조준이 중단됩니다. 게임 중 장시간 인식이 끊기면 마우스로 전환합니다.
- 초기 대기 화면에서는 다음 체험자를 기다리며 얼굴이 없다는 이유만으로 웹캠을 종료하지 않습니다.
- 카메라 오류 후 다음 Reset에서는 웹캠을 다시 준비합니다. 장치 오류가 지속되면 INPUT MODE의 웹캠 재보정을 사용합니다.
- 빈 좌석에서 자동 공격하거나 초기 화면이 자동 시작되지 않는지 확인합니다.
- 장시간 웹캠 반복 운영은 실제 얼굴·카메라 환경에서 별도로 확인합니다. 자동 마우스 반복 테스트는 이 검증을 대신하지 않습니다.

## 운석 충돌 / 조종석 손상 (2026-08-29)

- 운석은 조종석 앞 경계에서 사라지며, 유리 균열·Console Spark·HP Warning으로 피격을 표시합니다. 카메라는 흔들지 않습니다.
- 현재 Scene 기본값은 `PlayerSystem > PlayerHealth > Game Over Policy = NormalMode`입니다. HP 0이면 `MISSION FAILED` 결과를 거쳐 기존 격납고 메뉴로 돌아갑니다. 실패 없이 계속하는 행사는 Inspector에서 `NoFailExperienceMode`를 선택하세요.
- `PlayerSystem > CockpitDamagePresentation`에서 HP 단계(기본 70/40/20%), Flash 길이, 가장자리 강도, 스파크·경고음 간격을 조절합니다. 핵심 HUD를 장식 Monitor 목록에 넣지 마세요.
- 운영자 Reset/다음 플레이 시작 시 균열·스파크·장식 패널 고장이 모두 초기화되어야 합니다. 초기화되지 않으면 운영을 중단하고 결과와 함께 보고하세요.
- 조종석 geometry를 수정할 때에는 `LaunchSystem/CockpitGeometry/ShipCollisionBoundary`가 조종석보다 바깥에 있는지 확인하세요(현재 전방 2.65m, 추가 여유 0.12m).
- 자동 검사 범위와 현장 미검수 항목은 `Docs/CockpitDamageQA/REPORT.md`에 있습니다.

### 강화된 Cockpit Impact 연출

- 피격 시 큰 Spark와 잔여 Spark, 짧은 국소 White/Orange Flash, 금속·유리 충격음, 모니터 Static, 누적 Scorch가 함께 나타납니다. HP가 20% 미만이면 가장자리 공기 누출과 작은 누출음이 추가됩니다. 카메라 강제 흔들림은 없습니다.
- 기본 HP 단계 70/40/20%는 유지되며, 유리만 10% 미만에 최종 손상 단계 4를 사용합니다. `CockpitDamagePresentation`의 `Fractured Glass Below`, `Impact Spark Count`, `Residual Spark Seconds`, `Air Leak Volume`으로 조절합니다.
- 개발자 모드에서 F5로 본게임에 진입한 뒤 운석을 조준하지 않고 충돌을 관찰할 수 있습니다. 360 Simulation에서는 위쪽도 둘러보세요. 상단 손상 지점은 기본 HUD를 가리지 않도록 위쪽 프레임에 배치했습니다.
- R Reset과 격납고의 다시 하기를 각각 확인하세요. Crack / Scorch / Spark / Vapor / Dust / 누출음 / 모니터 오류가 다음 플레이에 남으면 안 됩니다.
- 높은 음량으로 먼저 시험하지 마세요. 실제 헤드폰/HMD에서 금속·유리 충격음과 Spark가 불편하지 않은지 운영 전 확인해야 합니다. 검증 범위는 `Docs/CockpitImpactQA/REPORT.md`를 참조하세요.

최신 시점/난이도 변경과 테스트 범위는 `Docs/UnifiedLookQA/REPORT.md`를 확인하세요. 이전 360 Simulation 보고서의 ‘Extreme에서만 360°’ 설명은 현재 버전에 적용되지 않습니다.
