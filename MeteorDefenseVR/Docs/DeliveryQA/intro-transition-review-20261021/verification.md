## 재현 결과 / 2026-10-21
800×600 / 1280×720 모두 로딩 중 Space 및 설정 중 Enter를 누르면 Intro로 넘어갔다. Before/verification.txt의 blocks=False와 원본 PNG를 보존했다. 자연 진행의 8개 상태 도달, 튜토리얼 중 설정 닫기 후 복귀, 출격 중·설정 중 재시작은 두 해상도 모두 성공했다.
최초 before.xml은 테스트 도메인 리로드의 클로저 예외로 제품 결함이 아니다. before-render.xml에서 합성 키보드 이벤트로 두 입력 결함을 재현했다.

수정 범위: 시작 입력의 공통 조건. 로딩·설정·교육·보정·일시정지 중 키보드와 시선 시작을 막고 차단 중 시선 누적을 초기화한다. 교육 측 InputBlocked는 보존한다. 최초 구현에서 어셈블리 참조 오류가 발생하여 PC 쪽에서 조건을 전달하도록 수정했다. 현재 회귀 검사 중.

## 증거 해석
- Before와 After의 원본 PNG 및 visible-text.txt, verification.txt를 분리 보존. 800×600 원본의 튜토리얼/빠른 연습/격납고/입력 차단 화면, 1280×720 전환 연락시트, 나머지 세 해상도의 튜토리얼/설정/전투 진입 원본을 눈으로 확인했다. 선택된 표본에서 안내와 설정 버튼이 잘려 없어지거나 다른 패널에 가려지는 추가 결함은 확인하지 않았다.
- 자연 전환의 before 그림은 상태 이벤트 직전에 렌더된 프레임이다. 상태 로그 자체는 이벤트 뒤 상태이므로 그림과 상태 표기를 혼동하지 않는다.
- .03/.18/.55초는 캡처 목표 시각이다. Enter 입력 헬퍼와 일시정지 검사 대기로 첫 Intro 및 Tutorial 표본이 늦어질 수 있다. 정확한 해당 시각의 모든 프레임을 검증했다고 주장하지 않는다.
- rapid는 상태 API를 통한 강제 빠른 진행이고 자연 사용자 동선과 구분한다. 자연 진행은 합성 상대 마우스 입력과 실제 무기 격추 콜백을 사용한다. 설정 버튼은 onClick 이벤트, Esc/Enter/Space는 InputSystem 큐를 사용한다.
- 별도 압축 해제 실행과 GitHub 공개 검증은 아래에 결과를 추가한다.
